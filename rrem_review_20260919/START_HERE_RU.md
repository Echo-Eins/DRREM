# RREM: повторная проверка и экспериментальная исправленная ветка

Дата аудита: 19 сентября 2026 года.

## Что здесь есть

`original/` — неизменённые три присланных файла. `AUDIT_RU.md` — результаты проверки и исследовательские выводы. `RESEARCH_ADDENDUM_RU.md` — поправки к научной программе и следующие эксперименты.

`rrem_repaired.py` — отдельная экспериментальная реализация. Она **не доказала превосходство на OpenOrca**. В ней исправлены проверенные ошибки производных, оценки, управления шагом и протокола. Изменена также функция нейрона; поэтому это новая исследовательская ветка, а не побитово совместимый патч оригинала.

`evaluate_original_readonly.py` — маленький адаптер для повторной оценки **существующего оригинального чекпойнта**, без изменений его весов и без переписывания динамики. Он отключает изменение общих порогов во время оценки. Это самый дешёвый первый эксперимент.

`tests/` и `results/` содержат исполняемые проверки и полученные результаты. Autograd используется только в диагностических файлах. В обучении новой машины нет `backward()`, `autograd.grad`, BPTT, EqProp, поиска неподвижной точки, ограничения спектрального радиуса или требования контрактности.

## Что реально проверено

Проверки выполнены на CPU, PyTorch 2.10.0, двумя потоками. Нет проверки CUDA, производительности на RTX 3080 и совместимости с конкретной установленной версией вашего внешнего загрузчика.

Проверены аналитические производные нейрона, фаз, вентилей, чтения и связанного входа; FF с отдельными положительным и отрицательным вкладами; точность локального правила относительно явно определённой локальной цели; отсутствие изменений параметров при оценке; границы ответов и горизонтов; масштаб обновления при уменьшении сигнала; повторяемость восстановления из чекпойнта; численный проход N=256, L=2, 8 хопов, 9 каналов и все 8 голов.

**Не выполнен научный обучающий прогон на OpenOrca.** Присланных `drrem.config`, `drrem.data.openorca`, манифеста выборки, данных, чекпойнтов и JSONL-логов здесь нет. Числа 8,07 → 5,33, 4,77 и 4,00 остаются результатами, сообщёнными пользователем, а не независимо воспроизведёнными результатами аудита.

Случайные вещественные тензоры в тестах являются алгебраическими проверками, а не синтетическим языковым корпусом. Короткие фрагменты присланного README используются только как буквальные байты для проверок протокола, сериализации и вызова обучающего интерфейса. Эти проверки не измеряют качество усвоения языка и не заменяют разрешённый OpenOrca-прогон.

## Запуск проверок

Из распакованного каталога:

```bash
bash run_checks.sh
```

Для них нужен только установленный PyTorch и стандартная библиотека Python. Не следует менять рабочий CUDA/PyTorch-стек ради запуска этих CPU-проверок. На других устройствах и версиях небольшие численные отличия допустимы; пороги точности тестов относятся к float64 CPU.

## Сначала переоценить старый чекпойнт

Скопировать `evaluate_original_readonly.py` в существующий каталог `drrem/`, рядом с **оригинальным** `rrem.py`. Из корня вашего проекта:

```bash
python -m drrem.evaluate_original_readonly runs/rrem/rrem.pt \
  --resp-max 64 --batch 32 --eval-batches 3
```

Путь к чекпойнту и параметры данных должны совпасть с вашим исходным опытом. Адаптер не воспроизводит сам тренировочный прогон; он проверяет уже сохранённую машину при замороженных общих параметрах. Отдельно нужно оценить документно-независимый test, который не использовался для выбора темпа.

## Запуск новой ветки в исходном проекте

Скопировать `rrem_repaired.py` в `drrem/`, не заменяя `rrem.py`:

```bash
python -m drrem.rrem_repaired --selfcheck
python -m drrem.rrem_repaired --micro --steps 60 --batch 32 \
  --name local_all --set device=cuda
```

Этот путь использует ваш существующий `DataConfig` / `OpenOrcaBytes`. Их интерфейс восстановлен из присланного исходника, но сами они здесь отсутствуют: реальную интеграцию ещё нужно проверить. `--prompt-max` управляет самостоятельным JSONL-загрузчиком; у внешнего загрузчика размер промпта определяется его собственным `DataConfig`.

Новая ветка использует обычные байты UTF-8. **CNN-фронтенд и BPE в неё не добавлены.** Ни их обучение, ни их сравнение с байтами не следует приписывать этой реализации.

### Контроль: только линейное чтение с действительно замороженными признаками

```bash
python -m drrem.rrem_repaired --micro --steps 60 --batch 32 \
  --name readout_only --set device=cuda tie_input=False \
  freeze=W,gate,E_in,phi,theta ff_weight=0 hop_loss=last
```

С тем же seed начальные входные представления совпадают с tied-вариантом, но затем остаются постоянными. Заморожены не только S/A, но и вход, вентили, фазы и пороги. Для оценки именно представлений **обученного** ядра нужны копирование его состояния и отдельное переобучение головы: этот CLI-контроль сам по себе стартует со случайного ядра.

### Контроль вспомогательной потери на ранних хопах

```bash
python -m drrem.rrem_repaired --micro --steps 60 --batch 32 \
  --name local_last --set device=cuda hop_loss=last
```

Оба режима читают все горизонты. `hop_loss=last` не запрещает глубокие вычисления: убирает только прямую CE-супервизию ранних хопов. FF при ненулевом весе всё ещё действует на каждом хопе своей пары прогонов.

### Отдельная абляция NS-направления

```bash
python -m drrem.rrem_repaired --micro --steps 60 --batch 32 \
  --name local_ns --set device=cuda muon=True
```

Это **не точная копия стандартного Muon**: после преобразования направления восстанавливается норма исходного согласованного сигнала. Классификатор/embedding по-прежнему получает обычный локальный строковый шаг. Эта ветка не имеет доказанного преимущества над `muon=False`.

## Явные экспорты настоящих данных вместо исходного загрузчика

```bash
python rrem_repaired.py --micro --steps 60 \
  --train-jsonl /path/to/openorca_train.jsonl \
  --dev-jsonl /path/to/openorca_dev.jsonl \
  --test-jsonl /path/to/openorca_test.jsonl
```

Строки должны иметь исходный `id`, `response` и либо `prompt`, либо `system_prompt` + `question`. Экспортируется настоящий разрешённый срез OpenOrca; скрипт не создаёт, не подменяет и не скачивает корпус. Проверка ID обнаруживает пересечение разделов, но сама по себе не доказывает происхождение текста: для этого нужен внешний манифест и хеши.

Внешний проектный загрузчик не предоставляет здесь весь список train-ID. Для него CLI проверяет пересечения встреченных обучающих батчей с оценочными, но не доказывает полноту разделения неизвестной реализации загрузчика.

## Метрики и чекпойнты

Лог содержит BPB и accuracy отдельно по каждому горизонту и уровню, число валидных целей и кривые по хопам для всех горизонтов. `evaluate(..., hops=H)` применяет выбранное число хопов также к истории промпта; период фазы не меняется вместе с H.

`local_loss` — локальная predictive CE; FF-loss и стоимость являются отдельными членами. Не следует подменять BPB суммой всех этих членов. Шаги и нормы — диагностические значения, не критерий интеллектуальных возможностей.

Чекпойнт содержит веса, пороги, фазы, моменты оптимизатора, темп и счётчики. CLI сохраняет также генератор self-negatives. Поддерживается точный перезапуск **на границе батча** при том же детерминированном загрузчике, данных, размере батча и конфигурации. Идентичность датасета и порядка внешнего загрузчика сама собой не гарантируется.

```bash
python -m drrem.rrem_repaired --micro --steps 120 --batch 32 \
  --name local_all --resume runs/rrem_repaired/local_all.pt --set device=cuda
```

`--steps` задаёт итоговое число батчей, а не количество дополнительных. Для нового опыта используется новое имя; существующий лог без `--resume` не дописывается.

## Границы реализации

Гомеостаз действует только при обучении на ответах и не является доказательством самостабилизации. По умолчанию ζ фиксирован, а `pace=False`: настройка по development — метаобучение, не «обучение без скорости». `pace=True` — отдельный необязательный эксперимент.

Мягкая цена передачи учитывает квадрат **эффективного** синаптического сигнала `(g * W * pre)^2`. Это устраняет простую возможность удешевить ребро уменьшением g и увеличением W. Но это всё ещё прокси, не измеренный расход электроэнергии и не количество операций GPU. По умолчанию цены нулевые; их вклад следует включать отдельными абляциями.

Локальная производная не проводит всю ошибку по всем возвратным путям и по всей прошлой последовательности. Непосредственный переход из одного состояния в другое и отложенная польза этого перехода — разные задачи присвоения заслуг. Полноценный обучаемый halting, динамическая разреженная маршрутизация, ускоряющее вычисления разреженное ядро, CNN/BPE и смысловой анализ спонтанных каскадов **не реализованы**.

Термин «три фактора / eligibility» не означает классическое парное STDP. Основное правило новой ветки — локальная производная predictive/FF-цели с пресинаптической временной eligibility. Оно ближе к supervised three-factor learning, чем к чистому pair-STDP. Переименование этого правила в STDP не сделало бы его более биологическим или более точным.

## Контроль без замены функции нейрона

Есть дополнительный режим `neuron_mode=legacy`. При одинаковых параметрах он воспроизводит исходную свободную динамику, сохраняя исправленное локальное обучение и чистую оценку:

```bash
python -m drrem.rrem_repaired --micro --steps 60 --name corrected_legacy \
  --set device=cuda neuron_mode=legacy hop_loss=last ff_weight=0 muon=False
```

Совпадение четырёххопового forward с оригиналом проверено до порядка 10⁻¹⁶. Этот режим намеренно сохраняет старую функцию порога, фиксированную норму r и старый фазовый период — это контроль для отделения эффекта нового правила от изменения нейрона. Называть его «полностью исправленной самостабилизирующейся динамикой» нельзя.
