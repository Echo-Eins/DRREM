# DRREM: активные наборы узлов, память, критики и бюджет вычисления

Дата: 24.09.2026. Статус: **план и спецификация; новая машина ещё не реализована и не обучена**.

Документ объединяет обсуждение нескольких активных узлов, обучения маршрутизации,
критиков уровней, биологических механизмов памяти, усталости и дополнительного
ресурса за полезную работу. Пользователь выбрал подготовку плана и точной
спецификации без написания рабочего кода и запуска обучения.

Ниже определён первый реализуемый вариант, отдельные контрольные варианты и
условия перехода между этапами. Численные начальные настройки — гипотезы для
калибровки на train, а не уже найденные оптимумы. Новая ветка не подменяет
`MachineV2`, событийную STDP-машину, `causal_transport` или `packet_transport`.

## 2. Цели и критерии, которые нельзя смешивать

1. Повысить качество преобразования одного контекста несколькими собственными MLP узлов.
2. Научить выбирать полезные назначения и сообщения с меньшей дисперсией кредита.
3. Проверить контекстную память принимающего узла, сохраняемую при прекращении активности.
4. Получить локальные производные от критиков, согласованные с конечной задачей.
5. Распределять ограниченный ресурс по полезным вычислениям, сохраняя память.
6. Добиться реальной экономии времени/памяти при сопоставимом качестве.
7. Проверить адресуемое связывание и свободные ответы, отдельно от статистики текста.

Наличие механизма, изменение его весов, его использование, причинная полезность
и преимущество после переобучения — пять разных утверждений. Для каждого нужны
свои свидетельства. Строгая монотонность внутренней энергии не является
гарантией монотонности CE, истинности ответа или биологической достоверности.

Биологическая мотивация: амплитуда одного сигнала не содержит самостоятельно
всего контекста. Значение определяется тем, какой нейрон/синапс активен, временным
рисунком, совместной активностью популяции и состоянием принимающей сети.
Подпороговые потенциалы и дендритная интеграция, активность сети и кратковременные
изменения синапсов дают разные механизмы зависимости от прошлого. Из этого не
следует, что кора исполняет наш BPTT-критик или выдаёт ток за строгое снижение CE.

Инженерный перенос проверяется по частям: адрес узла и популяция → маршруты и
набор K; состояние получателя → m_i; зависимость от использования → a_i/r_i;
отложенная модуляция пластичности → eligibility и обучающий сигнал. Векторный
узел с собственным MLP — вычислительная единица, а не точная модель одиночного
биологического нейрона. Подавление активности, стирание памяти, тормозный ток
и нейромодуляция пластичности не объединяются в одну переменную «энергии».

## 3. Конфигурация первого варианта

Рабочее имя: `FrontierTransportMachine`. «Активный набор» — адреса и отдельные
векторные состояния не более K узлов каждого уровня на текущем хопе. Независимые
деревья маршрутов не разворачиваются; входящие сообщения объединяются у получателя.

| Поле | Начальный контракт |
|---|---|
| Уровни / узлы | L=3, N=1024 самостоятельных узла на уровень |
| Содержимое узла | Пакет d=128; своя проекция 128→48, разделение gate/value по 24, SiLU(gate)×value, проекция 24→128; своя RMS-нормировка |
| Активность | K на каждый достижимый уровень; K — верхняя граница при усталости |
| Сетка K | 1, 4, 8, 16, 32, **50, 60**, 64; полноценное обучение только отобранных после профилирования вариантов |
| Хопы | H=20 в контроле; затем H_min=3, H_max=20 в адаптивном режиме |
| Граф | Все внутрислойные связи и обе стороны соседних уровней; отдельно отключаемые координатные 1↔3 |
| Вход | Обучаемая таблица 257×128; текущий байт входит только через первый уровень |
| Выход | Один сборщик третьего уровня и один конечный декодер h1+7MTP |
| Граница документа | BOS/EOS=256; EOS обучается и завершает генерацию; исключён из bpb и бюджета сырых байтов |
| История | Причинное внимание к предыдущим байтам, окно 1023; общий контекст уровня за хоп |
| Память узла | Сначала выключена; затем d_m=32, четыре группы по 8 координат |
| Оптимизатор эталона | Обычный Adam, lr=1e-4, betas=(0.9,0.95), weight_decay=0; отдельная train-калибровка при необходимости |
| Численная точность | Эталон CPU FP64/FP32 на малых задачах; обучение CUDA BF16 с FP32 для чувствительных операций |
| Начальная ширина BPTT | W=32 байта, полный градиент через все исполненные хопы внутри окна; контроль W=16/64 |

K=1 у новой машины не объявляется эквивалентом packet1: здесь возможно по одному
узлу на нескольких уровнях одновременно, иной обмен сообщениями и общая история.
Входная проекция, собственные MLP, память и адресные признаки учитываются в полном
числе параметров. Наличие спайков или физиологической фазы не заявляется.

## 4. Точный порядок вычисления

### 4.1. Две оси времени

`t` — абсолютная позиция байта документа; `h` — хоп внутри обработки этого байта.
Состояния и случайность принадлежат `(document_id, t, h)`, а не номеру строки батча.
При смене документа сбрасываются память, усталость, eligibility, история,
документные счётчики использования и бюджет. Глобальная обучающая EMA загрузки
хранится с весами, обновляется только после батча и заморожена при inference;
она не получает будущую часть текущего документа. Padding не продвигает оси времени.

Эталон выполняет байты последовательно, документы батча — независимо. Внутри
хопа обновления всех уровней синхронны и читают только снимок предыдущего хопа.
Порядок Python-цикла по уровням не должен создавать дополнительный переход.

Разделяются `F_h` — узлы, реально исполнившиеся на последнем принятом хопе,
и `Z_l` — последний принятый набор содержимого уровня l. Источники следующего
транспортного шага берутся только из F_h. Если уровень не получал сообщения,
его Z_l сохраняется для критика, конечного чтения и сводки истории; это не
необъявленный источник новых сообщений. До первого посещения Z_l пуст и имеет
явную маску `unreached`. Последний Z_3 сохраняется при возврате сигнала вниз.

### 4.2. Начало байта и достижимость

На входе `step(x_t, state)` имеется только уже прочитанный префикс до `x_t`.
Память узлов фиксируется для чтения на весь solve текущего байта. Первоначально
есть один виртуальный источник с embedding `x_t`, соединённый с первым уровнем.
После первого хопа он удаляется: текущий байт не инжектируется скрыто во все уровни.

Пока достижим только первый уровень, другие не исполняют MLP. Затем доступность
распространяется по настоящим рёбрам предыдущего активного набора. При достаточном
ресурсе выбирается не менее одного получателя на каждом достижимом уровне.
При выключенных перемычках путь через три уровня требует трёх обновлений.
На первые три хопа резервируется реальная стоимость доставки; отказ усталости
не может молча породить ответ из нулевого третьего уровня. Неудача доставки —
явная ошибка контракта, а не скрытый запасной декодер.

Резерв обеспечивает цену операций, но сам по себе не отменяет запрет r_i. При
достижимости без допустимых узлов возвращается `delivery_failure`; диагностика
отдельно показывает причину. В основном пилоте N≫K и восстановление между
исполнениями должны обеспечивать доставку; это проверяется, а не предполагается.

### 4.3. Оценки рёбер, выбор получателей и сообщения

Для каждого активного источника j и разрешённого назначения i вычисляется:

`s_ij = <Q_l norm(z_j), k_i + P_l m_i>/sqrt(d_addr) + b_ij - gamma_a*a_i`.

`d_addr=32`; `k_i` — ключ узла; `m_i` — его прочитанная память, ноль в контроле.
`b_ij` хранится только для существующих рёбер. В fatigue-off `gamma_a=0`.
В пилоте с усталостью `gamma_a=0.1`; контроль gamma_a=0 сохраняет только r_i.
Отдельный ресурс допуска может запретить узел независимо от величины score.
Отсутствующее ребро имеет ровно нулевую вероятность; `-inf` не заменяется
большим конечным штрафом. Самосвязи допускаются как в пакетном контроле.

Оценка назначения: `q_i = logsumexp_j(s_ij) - log(number_of_allowed_sources_i)`.
Нормировка убирает автоматическое преимущество назначения только из-за числа
источников. Для каждого уровня выбирается набор адресов A_l размера до K.
Затем только для выбранных назначений:

`alpha_ij = softmax_j(s_ij + log(beta_j))` по разрешённым активным источникам;
`u_i = sum_j alpha_ij * T_type(i,j) norm(z_j) + P_mem,l m_i + c_l`;
`z_i_new = u_i + step_scale * MLP_i(u_i)`.

MLP_i сам применяет свою RMSNorm к u_i перед проекциями gate/value; в этой
ветви нет второго неявного нормирования. Общая norm в формуле сообщений
относится к источникам, а не заменяет собственную норму принимающего узла.

`beta_j>0` — вес источника, сохранённый при его выборе на предыдущем хопе;
у виртуального источника beta=1. Веса не умножаются на содержимое повторно.
После выбора получателей `beta_i=softmax(q_i/T)` по выбранным адресам уровня;
сохраняются z_i и log(beta_i). Таким образом, beta не исчезает при следующей
RMS-нормировке пакета и имеет явного дифференцируемого потребителя.

`step_scale=1/sqrt(2*H_ref)`, `H_ref=20`, не меняется при раннем halt.
`T_type` — общие 128×128 преобразования для семи типов обычных блоков;
для координатных перемычек в первом варианте тождественное преобразование.
Новый механизм передачи содержимого явно отличается от старых edge-bias.
Начальный matched-контроль имеет `T_type=I` без обучения; обучаемые T — абляция.
Перенос полной матрицы 128×128 на каждое ребро не входит в первую реализацию.

Состояния выбранных узлов остаются раздельными. Слияние происходит у конкретного
получателя, а не усредняет весь уровень в один рабочий пакет. Повторное посещение,
переход 3→2→1 и координатный 3→1 допустимы. Уменьшение набора не удаляет память узла.

### 4.4. Общая история и конечное чтение

Из принятого активного набора каждого уровня вычисляется сводка `p_l` с
весами `softmax_i(w_collect,l^T norm(z_i) + log(beta_i))`. Для ещё не достигнутого
уровня сводка нулевая с отдельным флагом; читать выход из такого Z_3 запрещено.
После завершения байта эти три сводки поступают
в историю с абсолютной позицией t. На хопе текущего байта внимание читает только
позиции `<t`: запрос уровня строится из разрешённых входящих сообщений предыдущего
хопа; результат `c_l` общий для его кандидатов. Новые K/V текущего байта не могут
попасть в это чтение. Нет отдельного временного attention для каждого из 60 узлов.

Это сознательная новая организация истории, поэтому обязательны контроли:
attention / одинаковые проекции с равномерным прошлым / без истории.
После halt сборщик третьего уровня даёт d=128, final norm и h1+7MTP logits.
Выходная причинная ridge-коррекция включается отдельным флагом и сравнивается
с отключением при одинаковом остальном вычислении. Для потокового режима нужна
реализация с проверкой по независимой прямой ridge-задаче, включая все горизонты.

Ridge выключен в первом эталоне. При включении признаки и базовые logits
позиции t сохраняются исторически. Запись цели горизонта k разрешена лишь при
поступлении фактического байта t+k: сначала разрешаются созревшие прошлые записи,
затем делается новый прогноз. Непрочитанные labels не лежат в cache; незавершённые
горизонты отбрасываются на EOS. Прямой oracle решает prefix ridge по тем же
сохранённым признакам и уже наблюдённым residual-целям, без повторного вычисления
признаков новыми весами. Изменение порядка этой операции — отдельная модель.

## 5. Обучение выбора и распределения сообщений

### 5.1. Три обязательных маршрутизатора

| Режим | Что сравниваем |
|---|---|
| R0: равномерный | K разных допустимых получателей без обучения выбора членства; тот же банк MLP и лимит исполнений, полная цена измеряется |
| R1: стохастический | Последовательный выбор K адресов без возвращения; точные log-prob условных распределений и score-function кредит |
| R2: top-K с исследованием | Дифференцируемые веса сообщений и итогового смешивания внутри исполненного набора; дискретная граница явно остаётся |

У всех трёх режимов одинаковы alpha/beta и банк преобразований. R0 отключает
обучаемый выбор членства набора, но сохраняет обучение смешивания сообщений.
Полностью равномерные alpha/beta — отдельная абляция: её нельзя смешать с R0
и приписать разность только выбору адресов.

R1 — корректное расширение стохастического контроля; вероятность набора не
вычисляется как K независимых выборов с возможными дублями. Baseline получает
состояние **до конкретного действия**, уровень, h, оставшийся бюджет, степень
достижимости и сводку причинной истории. Его regression loss не обновляет тело.
Возврат включает все затронутые последующие supervised позиции внутри объявленного
окна кредита, включая действия на контексте. За пределами окна кредит усечён явно.
Для минимизации loss суррогат R1 равен
`sum_a stopgrad(G_a - b_a) * log pi(a | state_before_a) / D`:
G_a — сумма последующих взвешенных CE в этом окне, D — общий h1-denominator;
условные log-prob суммируются по выборам, хопам и уровням, а не усредняются по K.
При K-подвыборе baseline для следующего адреса видит уже выбранные адреса,
но не текущий случайный выбор. Выбранные MLP исполняются после сборки набора.

R2: начальная доля исследования 1/8 мест, не менее одного при K≥8. Сначала
выбираются K-K_explore лучших адресов по q, затем K_explore адресов равномерно
без возвращения из оставшихся допустимых. При нехватке допустимых K предварительно
сокращается до их числа. Дифференцируемый вес назначения `beta_i=softmax(q_i/T)` внутри набора
влияет на последующую передачу/сборку, поэтому loss имеет путь к q_i.
`T=1` сначала фиксирована. Участие hard top-K не выдаётся за точный градиент
изменения членства. У необработанного MLP нет известной контрфактической полезности.
Точное округление: `K_explore=floor(K/8)`, остальные K-K_explore — top-K;
при K<8 K_explore=0, стохастическое исследование обеспечивает отдельный R1.
Равные q разрешаются стабильным порядком ID; это отражается в метриках покрытия.

Температура, исследование и штраф загрузки калибруются раздельно. Режим мягкой
смеси всех узлов — только малый N=16/32 эталон и отдельный опыт; полный dense
warmup на N=1024 не подразумевается бесплатно. Straight-through, если понадобится,
получает отдельное имя и явное указание смещённости, не подменяет R1.

### 5.2. Покрытие, специализация и причинность

Измерять распределение посещений, число разных узлов, долю неиспользуемых,
энтропию, KL к uniform, частоту повторного посещения, эффективное число адресов,
нагрузку по уровням и семантическим группам примеров. Высокая энтропия сама по
себе не успех; малая энтропия сама по себе не ошибка.

Для борьбы с исключением узлов допускается штраф загрузки по EMA **прошлых**
батчей и небольшой исследовательский бюджет. Не требовать равномерности на каждом
токене. Текущая будущая часть документа не участвует в capacity/нормировках router.
Агрегированный auxiliary loss батча допустим в обучении; текущие решения forward
не могут зависеть от будущих токенов или чужих документов.

### 5.3. Проверка качества кредита

На одинаковых сохранённых состояниях: 16 route-seed, норма/дисперсия/парный cosine
градиента по группам; отдельно зависимость от длины возврата и размера батча.
На малой модели перечислить все маршруты и сравнить ожидаемый градиент R1 с
точной производной ожидания. На основной модели выборочно исполнить альтернативные
узлы с тем же контекстом и продолжением: это дорогая диагностика, не подсказка при
оценке. Проверить, предсказывают ли q и критик действительный порядок полезности.

Контроли MLP: свои обучаемые / замороженные / один общий с сопоставимым compute /
перестановка адресов / нулевой residual MLP. Они различают нехватку активной ёмкости,
плохую специализацию и доминирование attention. Матрицы T проверяются отдельно.

## 6. Память узла, время и локальные следы

### 6.1. Память содержимого

`m[doc, level, node, 32]`, четыре группы по 8 координат; начальные постоянные
времени в **байтах** `(8,32,128,512)`. На неиспользуемых узлах затухание реализуется
лениво по `last_memory_time`, математически точно как последовательное применение
коэффициента. Для control-no-decay коэффициент равен 1. Обучение временных
коэффициентов не включается на первом этапе.

Пусть сохранённое значение относится к commit позиции s<t. При чтении позиции t
`m_i_read(t)=exp(-(t-s)/tau)*m_i_saved(s)` покоординатно по группам; начальный ноль
имеет timestamp=-1. Read не мутирует сохранённое значение. В течение solve все
узлы читают этот снимок памяти начала байта. Последний принятый
выход каждого посещённого узла записывается в pending buffer. После вычисления
прогноза применяется один commit на узел:

`v_i=tanh(P_write,l norm(z_i_last))`;
`g_i=sigmoid(w_write,l · norm(z_i_last)+b_write,l)`;
`m_i_saved(t)=(1-g_i)*m_i_read(t)+g_i*v_i; last_memory_time_i=t`.

Инициализация gate: w_write=0, b_write=-2; проекция записи имеет обычную
fan-in инициализацию, P_mem нормируется по d_m. Это начальные настройки пилота,
а не биологические константы. Старый c-профиль здесь не обучается.

У непосещённого узла saved и timestamp остаются прежними: следующее чтение сразу
учтёт весь интервал, без двойного затухания. Непосещённые узлы не обнуляются.
Запись не получает target, CE, производную критика или будущие
байты как вход. Отклонённое предложение не попадает в pending memory.

Абляции: памяти нет / память сбрасывается перед каждым байтом / временной shuffle /
перестановка памяти между документами / фиксированные шкалы / без затухания /
write gate выключен. Отдельно проверять состав и порядок: те же символы и текущий
байт, но разные последовательности; роль запроса при одинаковом наборе фактов.

### 6.2. След участия и пластичность

Eligibility — отдельная величина, а не копия памяти содержимого. Первое точное
воплощение: сохранить локальные входы, адрес, время, выход и короткий граф каждого
исполненного MLP до обновления. Это позволяет суммировать вклад всех его посещений.
После этого допустим отдельный потоковый вариант локальных следов, проверенный
против эталона. Полная матрица eligibility на каждый синапс и документ может быть
дороже весов; факторизация должна быть названа приближением и оценена по памяти.

Глобальный модулатор умножает различные следы участия; всем связям не присваивается
одинаковое обновление. Такая схема не объявляется точным градиентом без отдельного
вывода. Pair-STDP, бинарные спайки и ReSuMe остаются отдельными контролями из
существующей событийной ветки, а не переименованием synthetic gradients.

### 6.3. BPTT и стоимость последовательности

Память узла между байтами создаёт настоящую последовательную зависимость. Эталон:
полный граф через все хопы и W=32 последовательных байта; на границе окна состояние
сохраняется численно и отсоединяется. Оптимизатор шагает только после backward.
Ни веса, ни память не мутируют in-place в ещё нужном графе.

Градиент через более старое состояние не заявляется. Сравнения W=16/32/64 имеют
тот же поток и байтовый бюджет; разный update cadence либо уравнивается накоплением,
либо явно выделяется как различие. MTP-цели за границей окна известны только loss,
не forward, и маскируются на настоящем конце документа. Train-time новые веса
не пересчитывают скрыто всю историю: старые представления являются историческими.
Для задач с задержками 128–512 отдельно проверить W=256/512 на малой модели:
сохранение численного состояния на 512 байтов не означает, что W=32 даёт градиент
правилу записи через этот интервал. Если ограничение кредита мешает, сначала
исследуется оно, затем обещается польза длительных eligibility-следов.

Векторизация по всем t, associative scan, parallel prefix или общий cache вместо
эталона разрешаются лишь после доказательства/теста эквивалентности. Пилот без
памяти сравнивается с memory-on на том же расписании; прежняя параллельная машина
остаётся отдельным внешним ориентиром скорости.

## 7. Критики: устройство и два разных назначения

### 7.1. Доступные входы

Один модуль критика на уровень. Он получает состояния и адреса его активных узлов,
маску, сводки других уровней, входящих сообщений и уже прочитанной истории,
прочитанную память, состояние ресурса и задачу/запрос только в том виде, в котором
они закодированы доступным префиксом. В режиме оценки будущего вычисления также h
и оставшийся бюджет. Число хопов не заменяет содержимое.

Первый энкодер множества: общая внутри уровня MLP `phi_l`, hidden=128,
вход `[norm(z_i), log(RMS(z_i)+1e-6), log(beta_i), node_embedding(16),
m_i_read, active_mask]`; pooling среднего и
суммы с явным счётчиком, затем MLP уровня. Адреса сохраняются, перестановка порядка
хранения набора не меняет оценку. Критик читает известные состояния; не исполняет
MLP всех 1024 узлов ради их оценки. Получение сводок и чтение памяти учитываются
в стоимости, даже когда число исполненных узлов мало.

### 7.2. C-grad: обучение локального сигнала

Для occurrence `(t,h,l)` получить на эталонном глобальном проходе целевую ошибку
`L_future` и `g*=d L_future/d Z_l`. В неё входят действительные последующие
потребители внутри объявленного W, attention, конечный decoder, ridge и будущая
запись памяти. Градиент по непрерывному пути при фиксированном discrete trace
не подменяет производную вероятности выбора маршрута.

Функция `V_l(Z_l, stopgrad(context), h, remaining)` обучается по:

`L_critic = mse(V_l, stopgrad(L_future))
          + lambda_g * mean((dV_l/dZ_l - stopgrad(g*))^2)`.

Значение и g* имеют одинаковую заранее указанную нормировку по supervised байтам;
калибровочный масштаб фиксируется по train и не пересчитывается по текущему dev.
`lambda_g` выбирается на отдельной train-validation части; начальная сетка
0,1 / 1 / 10 после нормировки шкал. Производные по входам требуют дифференцирования
самого критика второго порядка; это отдельная измеряемая цена, а не бесплатная MSE.
На обучении критика тело, его состояния и target-градиенты отсоединены.

Локальное обучение тела: вход каждого occurrence отсоединён, критик заморожен;
его `g_hat` умножается на локальный Jacobian MLP/преобразования сообщения.
Вклады всех occurrence общих весов **суммируются**, оптимизатор шагает один раз.
Поздний хоп, который не успевает повлиять на выход в данном графе, должен иметь
нулевой эталонный кредит. Нельзя присвоить каждому уровню одинаковую ошибку.

Критик принимающего уровня оценивает преобразованный пакет, включая возврат 3→1.
Он не переписывает оценку источника как собственную. Один scalar V даёт разные
производные по всем координатам: при K=60,d=128 это до 7680 компонент на уровень.

Для обучения сообщений набор выхода расширяется до `(Z_l, log(beta_l))`:
учитель сохраняет производную по обеим величинам, critic loss сопоставляет обе.
Локальный граф occurrence начинается с отсоединённых входящих пакетов, beta,
памяти и истории, но включает все его собственные projections, scores, alpha,
beta и MLP. Нельзя отсоединить beta до её локального producer и ожидать обучения q.
Через целочисленные ID градиент не заявляется.

### 7.3. C-budget: сопоставимая энергия для ресурса

`V_l` с меняющимся h оценивает разные задачи продолжения. **Нельзя** оплачивать
`V_l(h)-V_m(h+1)` как доказанное снижение одной энергии. Для бюджета выделяется
другой режим/голова тех же трёх модулей — единая фиксированная энергия `E(Z,C*)`.

Точный первый вариант: энкодеры уровней дают p_l; общая энергия задаётся

`E = softplus(b + sum_l v_l^T p_l + sum_(l<m) p_l^T R_lm p_m)`.

Это три модуля и явное согласование их выходов, без независимых несопоставимых
нулей энергии. `R_lm` учитывают взаимодействие уровней. При изменении уровня l
критик возвращает общую E и её частную производную по Z_l при фиксированных
остальных состояниях. Учитываются оба появления p_l в общем выражении;
нельзя отсоединить перекрёстные члены и назвать результат точным градиентом E.

На время одного solve заморожены веса критика, нормировки, C*, набор оцениваемых
целей по типу задачи и правило эталонного продолжения. C* содержит только
причинную информацию и фиксируется при начале этого solve. Адреса, маски и
содержимое активных наборов — часть оцениваемого состояния, а не скрытый context.
Текущие h, остаток B, a/r и число отказов не меняют C-budget: соответствующие
признаки, если нужны, берутся только из снимка C*. Это запрещает получать credit
просто за ход часов, усталость или расход бюджета. C-grad, напротив, получает
фактический remaining, поскольку предсказывает реальное продолжение.

Обучающий смысл E: CE+MTP после **фиксированных R=4 дополнительных транспортных
хопов** от вмешанного состояния, с тем же единственным конечным декодером, и
CE текущей позиции плюс следующих Q-1 позиций, первоначально Q=4 байта.
Далее эти Q-1 байта исполняются с фиксированными H=20 и теми же весами;
контроль Q=1 отделяет немедленную пользу от записи памяти. Для каждого solve
граница Q и маски целей фиксированы заранее, включая настоящий конец документа.
Этот эталон требует реального replay на train; стоимость R и Q входит в бюджет
исследования. Он одинаков
для before/after независимо от фактически потраченных хопов. R=4 — начальная
гипотеза, сравнить R=0 там, где выход уже достижим, и R=8 на train-validation.

Эталонный consumer отключает fatigue, halt и credit; его router не получает h,
а дополнительный attention зависит от состояния и истории, а не абсолютного хопа.
Его RNG индексируется относительным номером replay-шага от 0. Иначе одинаковое
состояние, достигнутое на другом хопе, имело бы другую задачу оценки. После R
выполняется обычный read/commit; будущие pending-записи включаются в оцениваемый
state. Общая E поэтому получает также сводку pending memory по уровням: две
траектории с одинаковым последним Z и разными будущими записями не тождественны.
Структурно недостижимый выход даёт метку invalid и не участвует в CE-регрессии;
основной R=4 при данной топологии обеспечивает эталонную доставку от входа.

Для pending применяется второй инвариантный к порядку pooling по записям
`[node_embedding, candidate_written_memory, write_mask]`; его результат входит
в p_l наряду с активным набором. Candidate memory вычисляется из принятого z
обычным write gate, с сохранением производной для проверяемого вмешательства.
Размер всех этих наборов и цена их pooling регистрируются. C-budget обучается
той же суммой value-MSE и gradient-MSE, что C-grad, но по собственному R/Q consumer.
Среднее по доступным координатам не меняет нормировку самого целевого loss.

Поэтому C-budget не выдаётся за точную замену C-grad на всех стадиях: у них разные
потребители. Объединить их можно только после проверки совпадения полезных
направлений. Эталонные продолжения используют одинаковую случайность; отдельно
проверяются фиксированные маршруты и честное повторное вычисление маршрутов.
Будущие байты используются для целей обучения, никогда как вход E при inference.

### 7.4. От данных критика до доверия ему

Собирать состояния всех уровней и всех достижимых хопов: нормальные, переставленные,
обнулённые, с испорченной памятью, альтернативными маршрутами, изменённой нормой,
неверным связыванием и ограниченными локальными возмущениями. Только состояния
одной естественной траектории не обучают поведение вне неё.

Разделить train-fit / train-calibration / train-confirmation по документам.
Измерять value error, calibration, gradient cosine, масштаб, знаки по квантилям
силы true gradient, ранжирование вмешательств и фактический CE после предложенного
шага. Проверять на новых хопах, длинах, K и бюджетах; перенос без проверки запрещён.
Обязательны контроль «обычный BPTT», точный кредит одного occurrence и прямой
векторный synthetic-gradient предсказатель без требования скалярного потенциала.

Первое применение — замороженные хорошие веса; затем совместное обучение с
обновлением эталонов. Сравнить 100%, 50%, 25%, 0% глобальных update-батчей.
Локальные и глобальные градиенты не суммировать дважды молча. Baseline графа
и critic-fit не меняют тело. Частота дорогого teacher-pass 1/1, 1/4, 1/16 —
отдельная ось после подтверждения качества. Учитывать весь teacher compute.

## 8. Усталость, ресурс и реальное выключение

### 8.1. Локальная адаптация и доступность

Отдельно хранить `a_i>=0` (адаптация) и `r_i in [0,1]` (доступность).
В микротакте, включая время отдыха:

`a_i <- rho_a*a_i + b_a*executed_i`;
`r_i <- clamp(r_i + recover*(1-r_i) - use*executed_i, 0, 1)`.

Начальные настройки пилота: `rho_a=exp(-1/8)`, `b_a=1`, `recover=1/16`,
`use=1/4`, допустимость `r_i>=use`. Ленивая реализация обязана совпасть с явной.
Адаптация и ресурс меняются по реально исполненным операциям, включая отвергнутые
дорогие предложения. Безусловное старение задаёт общий бюджет, а не стирание m_i.
Отдельный буквальный контроль: каждому узлу отнимается единица life на хоп, как
в прежнем `energy_budget`; не смешивать его с activity-dependent адаптацией.

В первой версии параметры усталости фиксированы. Обучаемые параметры допустимы
позже с положительными ограничениями и отдельной абляцией; старое вредное правило
c/g/kappa не переносится автоматически. Пополнение не увеличивает норму m или z.

### 8.2. Стоимость

Стоимость включает routing scores, исполненные MLP, передачу сообщений, attention,
критика, его входные производные, подбор шага, чтение/запись памяти и все повторы.
Сначала фиксируется аналитический счётчик MAC и операций; после профилирования
обучающий контроллер использует замороженную положительную модель стоимости
`c = c_fixed + c_nodes*n_nodes + c_edges*n_messages + c_history*n_history`.
Коэффициенты — по измерениям изолированных kernels на целевом GPU, не из текущего
loss и не из времени соседнего процесса. Счётчики и реальное wall time публикуются оба.
Приведённая форма — начало cost model: обязательны отдельные положительные члены
для candidate scores, pending-memory pooling, critic forward/input-gradient и
повторных проверок. B измеряется в единицах этой замороженной модели, не обещает
жёсткого срока в миллисекундах. Upper bound считается по максимальному числу
разрешённых операций предложения, а не по среднему времени удачных предложений.
Стоимость начальной оценки E, конечного decoder и обязательного commit/history
резервируется отдельно в начале байта и не расходуется на дополнительные хопы.
Teacher backward/replay входит в общий training ledger, а не маскируется под
бесплатную часть машинного бюджета inference.

Узел исключается **до** вызова MLP. Группировать `(document,node)` посещения,
исполнять grouped/batched GEMM, не материализовать отдельные копии весов для
каждого байта и кандидата. Адресные scores по всем разрешённым назначениям
считаются расходом даже при K=1. Sparse mask после плотного GEMM экономией не считается.

### 8.3. Пополнение только за новый результат

После принятого состояния вычисляется `E_new` тем же C-budget:

`gain = max(E_best - E_new - epsilon, 0)`;
`credit = eta * gain`;
`B_next = min(B_max, B - actual_cost + credit)`;
`E_best_next = min(E_best, E_new)`.

Перед исполнением резервируется верхняя граница цены предложения и проверок.
Если её нет, предложение не запускается; стоимость не может быть оплачена
задним числом ожидаемой наградой. После исполнения списывается фактическая цена.
`epsilon` и eta фиксируются по train-calibration; начальный epsilon — 95-й
процентиль абсолютной ошибки оценки **разности** энергий на парных вмешательствах,
а не заявленная статистическая гарантия. Проверить также epsilon=0 как контроль.

Единица стоимости c_ref — цена одного полного хопа при данном K, с routing и
проверкой критиком. Первый adaptive-пилот: B_0=6*c_ref с резервом доставки,
B_max=20*c_ref; eta=6*c_ref/max(median_train(E_initial),1e-6).
Контрольная сетка B_0 — 3/6/10/20 таких единиц, множитель в eta — 0/3/6/12.
Если резерв не помещается в номинальный B_0, вариант помечается infeasible;
его бюджет не увеличивается скрыто. Подбор идёт только на train-calibration.

E неотрицательна; при фиксированном оценщике суммарный credit за рекорды ограничен
`eta*E_initial`. Часть энергии без credit тоже уменьшает E_best. Повторное
ухудшение/восстановление, смена слоя, обновление критика или сброс E_best внутри
байта не создают новый ресурс. В любом случае действует H_max.

Ресурс общий на solve, локальная допустимость задаётся r_i. Вторая, отдельная
абляция направленно восстанавливает r_i участвовавших узлов, распределяя **тот же**
credit; глобальный и локальный ресурс не получают одну награду дважды.
Нельзя суммировать только положительные локальные выигрыши, игнорируя отрицательные
вклады: оплачивается один измеренный общий gain. Для направленного распределения
использовать нормированные положительные оценки вклада внутри этого потолка.

### 8.4. Монотонность и транспорт

Обязательная оценка критиком происходит после каждого предложения, включая
переходы назад. Два раздельных режима:

* `budget_only`: транспортный шаг может повысить E; он не получает credit.
* `strict_refinement`: после первичной доставки принимается только шаг с
  `E_new <= E_old + numeric_tolerance` при фиксированном E и C*.

Сначала проверяется обычное транспортное предложение, включая его новый набор ID.
Если оно не проходит, возможен один заранее оплаченный цикл коррекции его содержимого:
`g=dE/dZ_proposal`, `d=-g/(sqrt(mean(g^2))+1e-6)` на совместном наборе изменённых
уровней, `Z_trial=Z_proposal+alpha*d`. Начальный alpha_0=0.1; проверяются
alpha_0×(1, 1/2, 1/4, 1/8) по порядку, принимается первый допустимый вариант.
Beta и ID при этих пробах фиксированы; pending пересчитывается из Z_trial.
Нулевой градиент не создаёт искусственного направления. Все варианты сравниваются
с E старого принятого состояния, а не только с неудачным предложением.

Если ни один не подходит, состояние и pending memory сохраняются прежними;
потраченный compute и усталость сохраняются, credit=0. Изменение самого набора —
дискретное предложение со своей полной проверкой; ID никогда не интерполируются.
Отдельные контроли: только проверка без коррекции, коррекция без жёсткого rejection,
полный strict_refinement. Так цена и польза производной E отделяются от фильтрации.
Численный допуск FP32: `1e-6*max(1,abs(E_old))`; critic/budget вычисляются в FP32
и при BF16-теле. Энергия не округляется до BF16 перед сравнением.
Эталонный глобальный backward через корректирующий d включает его зависимость
от Z и, следовательно, вторую производную E. Вариант `stopgrad(d)` — отдельное
приближение; нельзя сравнить его с точным teacher и назвать градиенты равными.

Буквальное требование «монотонно с самого первого хопа» не теряется: выделяется
контроль `strict_all`, где фиксированный R=4 consumer позволяет оценить состояния
до достижения выхода. Если допустимый путь к выходу не найден в резерве,
фиксируется failure. Принудительный переход с ростом E не выдаётся за соблюдение
strict_all. Основной режим сохраняет начальный запас на подготовительную доставку.

Ни один режим не заявляет монотонность реального CE по факту убывания E.
При исчерпании B используется последний **принятый** набор третьего уровня.
Усталость прекращает вычисление; память содержимого не обнуляется. Критик может
одобрить STOP, но не выдаёт текст вместо единственного конечного декодера.
H_max считает предложенные транспортные хопы, в том числе отвергнутые; четыре
пробы alpha находятся внутри одного хопа и ограничены отдельно. Глобальные часы
усталости продвигаются на один тик на предложение; executed_i означает реальный
вызов собственного MLP. Повторное чтение критика не восстанавливает r_i временем
и не создаёт фиктивного нового исполнения MLP.

## 9. Совместное обучение и предотвращение ложной экономии

Эталонная цель: `L = [sum(mask_1*CE_h1) +
(1/7)*sum_(k=2..8) sum(mask_k*CE_hk)] / D`,
где D — число supervised h1-позиций окна, включая обучаемый EOS. Это прежняя
нормировка по h1, а не восемь независимо нормированных CE на границе документа.
Метрика h1 bpb отдельно исключает EOS; горизонты имеют собственные счётчики метрик.
В адаптивном этапе: `J = L + lambda_cost * measured_work_proxy`, отдельно от
critic-fit и routing-baseline losses. Начать с lambda_cost=0 и фиксированного
достаточного бюджета; усиливать стоимость только после получения работающего
предсказания. Уменьшение активности при провале CE не считается эффективностью.

На обучении применяются те же fatigue, halt, credit и commit, что на оценке.
Бюджеты варьируются по заранее записанному расписанию; начальная сетка — цена
3/6/10/20 полных хопов данного K, с реальным резервом доставки. STOP vs CONTINUE
сначала выбирается детерминированным бюджетом. Обучаемая остановка — следующий
контроль с оценкой полезности продолжения и сохранением жёсткого H_max.

Основной градиент обучает исполненный непрерывный граф. Дискретные STOP, смена
набора и принятие по порогу не становятся дифференцируемыми от наличия критика.
Для обучаемых дискретных действий — отдельный score-function estimator;
градиент по выбранной ветке acceptance явно назван условным/кусочным.
В score-function возврат включается и lambda_cost×последующая стоимость с тем
же denominator D. Просто прибавить дискретный счётчик операций к differentiable
loss недостаточно, чтобы научить выбор экономить вычисления.

Во время solve веса всех модулей заморожены. Обновления тела, критиков и baseline
разделены по ownership и выполняются после сбора необходимых целей. Пропуск
teacher-pass экономит compute только если действительно не строится его полный
граф. Время сбора teacher-данных и дополнительных продолжений не скрывается.

В первой P6 локально учатся только собственные MLP и их нормы; router, память,
attention, embedding и decoder заморожены либо получают явно учтённые глобальные
update-батчи. Это гибридный опыт. Затем границы расширяются по таблице:

| Группа | Источник кредита |
|---|---|
| MLP, T_type, P_mem, message projections | g_hat соответствующего принятого occurrence, входы отсоединены |
| q/key/edge-bias в непрерывных alpha/beta | производные по Z и log(beta); членство R1 отдельно получает score-function |
| Decoder и выходная norm | точный локальный CE+MTP backward от единственного выхода |
| Attention, collector и embedding | точный BPTT в первом гибриде; позже отдельная проверенная граница выхода каждого producer |
| P_write и write gate | точный BPTT через commit; локализация требует отдельной производной по m_saved(t), а не g_hat по z |
| Critic и routing baseline | только свои detached цели; не входят в обновление тела |

Расширение до локального обучения записи требует memory-head тех же критиков:
цель `dL_future/dm_saved(t)` на совершённых commit. Пока такой head не прошёл
T13 и проверки полезности, нельзя заявлять локальность обучения записи или
сокращение всего BPTT. Для каждого параметра manifest задаёт ровно одного владельца
градиента на update; повторные visits суммируются, общие ветви не считаются дважды.
На локальных батчах непринятые предложения не получают CE-кредит тела;
их фактическая стоимость остаётся в возврате дискретной политики.

Один цикл обучения: зафиксировать версии тела/критиков → собрать W-окно →
при teacher-pass сохранить целевые производные → вычислить разрешённые градиенты
тела → выполнить один его update → обучить critic/baseline на отсоединённом
снимке старой версии → отсоединить состояние на границе и продолжить поток.
Snapshot-version сохраняется с примерами; накопленные данные критика обновляются
по расписанию, чтобы обучение на устаревшем теле было измеряемым, а не скрытым.

Пластичность при чтении готовой модели — последующая отдельная серия: сначала
оценить новый блок, затем учиться на уже прочитанных байтах; сброс на документ.
Не смешивать её выигрыш с преимуществом постоянных весов и быстрой памяти узла.

## 10. Порядок опытов и контрольные варианты

| Этап | Работа | Контроли и результат для перехода |
|---|---|---|
| P0 | Инвентаризация данных, очередей, checkpoint, исходников и свободного устройства | Воспроизводимый manifest, старые результаты отделены от новых |
| P1 | Малый точный frontier-forward и grouped execution | Независимые эталоны графа, сумм токов, градиентов, причинности и resume проходят |
| P2 | Профилирование N=1024 и K-сетки без длинного обучения | Реальное время forward/backward/router/critic, память, число исполнений; выбрать доступные K |
| P3 | Stateless frontier, фиксированные H=20, обычный глобальный градиент | R0/R1/R2 при одинаковых данных; learned-vs-uniform и MLP-vs-controls; K=50/60 явно проверены хотя бы пилотом |
| P4 | Память узлов | matched no-memory, reset/swap/order, W=16/32/64; польза не объясняется только большим контекстом |
| P5 | C-grad и C-budget на замороженном теле | Ошибка/производные/реальный CE вмешательств; ещё не управлять ресурсом непроверенным критиком |
| P6 | Гибридные локальные обновления | Полный BPTT, точный occurrence-credit, synthetic gradients; все уровни/хопы; потом редкие teacher-passes |
| P7 | Усталость и бюджеты с обучением | Фиксированный compute, fatigue без credit, learned credit, контрольный credit; качество при одинаковом бюджете и времени |
| P8 | Монотонная коррекция и STOP | budget_only / strict_refinement / strict_all; цена поиска шага, отказы, доставка, финальный CE |
| P9 | Финалисты и семантика | ≥3 seeds, 10 МБ, независимое подтверждение после выбора, свободная генерация и контрфактические пары |
| P10 | Дополнительные механизмы | Только при указании оставшегося узкого места и отдельном контроле |

Не запускать полный декартов продукт. P3: короткий одинаковый бюджет до 0,25 МБ
для отсева численно неработоспособных вариантов, затем до 1 МБ и 3 МБ финалистам;
длинная точка — 10 000 000 целевых байтов. Малые ранние проигрыши не выдаются за
предел метода. Правила прекращения и выбор финалистов фиксируются до раскрытия
соответствующего dev; отбор по времени и байтам показывается раздельно.

Обязательная четвёрка P7 на одной архитектуре с памятью:

1. Фиксированные H/K без усталости.
2. Усталость без пополнения.
3. Усталость с независимым от текущего качества распределением сопоставимого ресурса.
4. Усталость с credit за новый минимум C-budget.

Для честного контроля 3 таблица распределений credit по стадии/затратам берётся
только из train-calibration и замораживается. Девелоперский вариант с replay
будущего расписания другой dev-модели не допускается. Равенство ресурсов проверяется
фактически: публикуются и кривые при одинаковом потолке, и интерполяция по реально
потраченным операциям/времени. Отдельно сравнить обученный режим с включением на
готовых весах, чтобы объяснить отличие от прежней отрицательной проверки.

## 11. Данные, стоимость обучения и независимость оценки

* Основной новый старт — с нуля на прежней фиксированной FineWeb-подвыборке.
  Поток и hash выбранных байтов одинаковы у пар. Перенос OpenOrca — отдельная
  серия с полным учётом прежних 24 008 387 целевых предъявлений и контекста.
* Сохранить прежние train/dev/test ID и дедупликацию. Train-fit/calibration/
  confirmation критиков — непересекающиеся документы; все их предъявления,
  вспомогательные backward/replay и использование текстов входят в ledger.
* Прежде открытые test512 считаются открытой исследовательской выборкой.
  Оставшиеся 1536 нельзя автоматически назвать нетронутыми без аудита истории.
  Зафиксировать ещё не использованное подтверждение до выбора финального checkpoint.
* Dev32 для кривых, dev128 для заранее заданных конечных сравнений. Финальный test
  не используется для выбора K, epsilon, температуры, этапа или коэффициентов.
* Новый последовательный loader читает документ от BOS, хранит state и курсор;
  каждый целевой байт оценивается один раз. Для коротких диагностических окон
  burn-in и перечитывания учитываются отдельно. Overlap не повторяет commit памяти.
* Счётчики: уникальные байты, целевые предъявления, контекст, EOS, critic labels,
  teacher passes, альтернативные продолжения, optimizer steps, суммарное GPU-время.
* При ровно 10 МБ последний неполный батч маскируется; не добавлять байты сверх
  лимита ради удобства формы. Не пропускать хвосты документов или незаметно
  заменять stream длинного документа несколькими сброшенными окнами.
* Сравнения по данным и по времени оба обязательны. Старую плотную модель
  оценивать на тех же целях; отличия контекста и бюджета предобучения указывать.

«10 МБ» означает 10 000 000 обычных h1-целевых предъявлений сырых байтов телу,
как в прежней серии; MTP и повторное предъявление тех же labels при обучении
критика не исчезают из отдельного счётчика supervision. Дополнительные уникальные
тексты критика не допускаются в основной паре: fit/calibration/confirmation
выделяются по документам внутри заранее зафиксированного train-пула. Confirmation
не участвует в fitting критика; прежняя встреча текста телом отражается в manifest.
Независимое подтверждение языковой модели использует отдельные документы.
Если число critic-label предъявлений различается, это сравнение при одинаковом
основном потоке, а не при одинаковом полном обучающем бюджете. Дополнительно
строится сравнение при фиксированных суммарных предъявлениях и GPU-времени.
R/Q replay и MTP не читают за согласованный data cap скрыто: на краю маскируются
недоступные labels, а контекстный lookahead, если разрешён протоколом, учитывается.

## 12. Метрики и критерии допуска

Для каждой модели сохранять h1 bpb, все 8 горизонтов, per-document суммы/счётчики,
парный bootstrap по документам, долю документов лучше и результаты каждого seed.
Считать corpus bpb по суммарным байтам, а не среднее bpb документов без объяснения.
Интервал по документам не заменяет разброс между seeds. Для большого числа
проверок использовать выделенное подтверждение после выбора, а не выбирать
лучшее из сотен интервалов на одном dev.

Стоимость: median/p95 времени, целевые байты/сек, GPU allocated/reserved,
память optimizer/состояния/графа, число реальных MLP, сообщений, route-score
оценок, attention-чтений, critic forward/backward, повторов и хопов. Публиковать
кривые качества против байтов, времени и измеренных операций.

Динамика: нормы состояний/весов/градиентов, насыщение, память и усталость,
покрытие узлов, значения E, реальный loss, credit/spend, причины halt,
отклонённые предложения, сохранность контекста после отдыха и возвратов.

Переход P5→P6/P7 требует на train-confirmation одновременно:

1. Нет утечки и численного нарушения контрактов.
2. Для заранее выбранного размера вмешательства paired mean конечного CE
   лучше нулевого вмешательства; 95% документный интервал не пересекает ноль.
3. Направление и масштаб градиента проверены по уровням/хопам и слабым координатам;
   сам по себе хороший cosine не достаточен.
4. Выигрыш сохраняется при честном replay маршрутов; фиксированный trace указан отдельно.

Если критик не проходит: сохранённые данные используются для диагностики;
он не получает управление бюджетом «на всякий случай». Если редкие teacher-passes
ухудшают качество, вернуться к более частым и показать отсутствие экономии.
Остановка NaN/Inf, недоставки, потери градиентов или несогласованного resume —
техническая неудача с сохранённым артефактом, не результат качества.

## 13. Семантика и свободная генерация

Сначала прежние 48 заданий и оба режима T=0,8/top-p=0,9 и T=1/top-p=0,95,
96 свободных байтов; greedy — диагностический контроль. EOS не исключается.
Полные исходные байты и тексты сохраняются, включая невалидный UTF-8 и повторы.
Веса не обновляются при стандартной генерации; быстрое состояние меняется ровно
так же, как в forward. Адаптация весов при генерации — другая явно названная серия.

Новые подтверждающие пары: перестановка имён и фактов, одинаковые префиксы кодов,
смена запроса при неизменных фактах, отвлекающий решённый пример, последнее
местоположение, отмена/обновление факта, несколько объектов, увеличение расстояния
64/256/512/1024 байта, английский и русский отдельно. Ответ начинается без
подставленного правильного префикса; forced-choice и teacher-forced пробы
публикуются отдельно от свободного ответа.

Обе версии пары должны следовать изменённым посылкам. Наличие буквы/цифры внутри
бессвязного текста не засчитывается. Автоматическая метрика дополняется просмотром
всех зачтённых ответов и заранее выбранной полной серии. Новые задания не
используются для настройки; их шаблоны/seed фиксируются до генерации.

Изолированная учебная программа связывания — отдельная последующая серия с
учётом синтетических обучающих примеров. Её результат не приписывается чистому
обучению на FineWeb. Для различения механизмов: swap памяти, lesion attention,
uniform routes, выключение MLP, заморозка critic/credit, тот же суммарный compute.

## 14. Обязательные тесты реализации

Малые искусственные тензоры и последовательности здесь — unit-тесты, не
доказательство языкового качества и не скрытый обучающий корпус.

| ID | Независимая проверка |
|---|---|
| T01 | Граф: полные внутренние/соседние связи, обе стороны, только разрешённые координатные перемычки |
| T02 | Синхронность: перестановка обхода уровней не меняет результат; один хоп не проходит два ребра |
| T03 | K разных назначений, нет выполнения невыбранных MLP; hooks и счётчики согласованы |
| T04 | Grouped MLP против простого цикла: forward, входные и параметрические градиенты, повторяющиеся ID |
| T05 | Суммы реальных сообщений, attention, memory read и MLP восстанавливают вход/выход каждого потребителя |
| T06 | R1: точная вероятность выбора без возвращения, ожидаемый gradient по полному перечислению |
| T07 | Нет вероятности запрещённого ребра при округлении CDF/BF16 и пограничном случайном числе |
| T08 | R2: finite differences внутри неизменного набора; отдельно граница top-K, нулевые/равные scores |
| T09 | Один документ/префикс не меняется от будущего суффикса, padding, другого документа и перестановки батча |
| T10 | Counter RNG определяется document/position/hop/action/seed; replay и checkpoint recompute повторяют выбор |
| T11 | Критик и baseline не получают targets в forward; градиенты critic-fit не меняют тело |
| T12 | Точные g* через настоящий оставшийся граф; нулевой кредит структурно недостижимых occurrence |
| T13 | Сумма всех локальных occurrence-градиентов с точным кредитом совпадает с глобальным градиентом соответствующих параметров |
| T14 | Cross-level энергия: finite differences общей E и частных производных; смена level ID не создаёт gain |
| T15 | При одинаковом содержимом энергия не меняется от часов/бюджета/усталости или внешней шкалы отчёта; изменение нормы z отдельно сверяется с реальным CE |
| T16 | Lazy memory/fatigue совпадают с явным покадровым эталоном; единицы byte/hop различаются правильно |
| T17 | Read-before-commit, ровно одна запись узла за байт, overlap без дублей, reset по документу |
| T18 | Усталость не стирает содержимое; отдых восстанавливает доступность; rejected update не пишет память |
| T19 | Бюджет: предварительное резервирование, полный расход проверок/повторов, без отрицательного остатка |
| T20 | Дробный credit не покупает целую операцию, цикл ухудшения/возврата не даёт повторной награды |
| T21 | Суммарное пополнение ограничено рекордным снижением E; локальная раздача не умножает общий credit |
| T22 | STOP/H_max/reserve: есть настоящий конечный пакет; strict_all failure не маскируется запасным forward |
| T23 | Монотонность только фиксированной E на принятой траектории; rejected trials оплачены |
| T24 | Весь BPTT на малом окне против ручного unroll; detach только на заявленных границах |
| T25 | h1+7MTP: независимый CE-oracle, границы документов/окон/EOS, отсутствие будущих целей в state |
| T26 | Ridge: независимый прямой prefix solve всех горизонтов, overlap и исторические записи |
| T27 | Native generation против того же training-forward, с теми же precision/compile/masks; будущая независимость |
| T28 | Resume восстанавливает веса, Adam, RNG, память, усталость, cache, cursor, counters и следующий update |
| T29 | NaN/Inf отклоняются до optimizer.step; принудительное прерывание не повреждает последний checkpoint |
| T30 | Viewer не меняет logits/маршрут/состояние; отображает реальный размер, единые шкалы и причину выключения |

CPU FP64 — для производных/алгебры, FP32 — основной численный эталон. Для BF16
зафиксировать допуски по независимому измерению; точное равенство RNG и адресов
остаётся обязательным при replay в том же численном режиме. Между FP32 и BF16
пограничные categorical/top-K решения могут различаться; это измеряется отдельно.
Численное равенство FP32 не выдаётся за совпадение CUDA
compiled/BF16. Полноразмерный preflight обязателен перед длинной очередью.

Контракт API (псевдокод, не выполненная реализация):

```python
init_document(document_id, device) -> DocumentState
step(byte_id, state, route_key, policy) -> StepOutput(logits, new_state, trace)
propose_hop(frontier_snapshot, memory_snapshot, context, route_key) -> Proposal
evaluate_level(level, joint_state, frozen_context, purpose) -> CriticOutput
reserve(proposal_upper_cost, ledger) -> Reservation | Stop
accept_or_reject(proposal, critic_snapshot, mode) -> Decision
commit_byte(accepted_trace, old_document_state) -> DocumentState
teacher_targets(trace, frozen_consumer, targets, horizon) -> DetachedTargets
local_gradients(occurrences, frozen_critics) -> GradientsByParameter
optimizer_update(gradients, optimizer) -> UpdateAudit
```

`StepOutput` не содержит будущую цель. `DocumentState` не хранит тренировочный
loss как информацию для будущего предсказания. Внутренние diagnostic targets
находятся в отдельном trainer-owned объекте. `trace` описывает и оплаченные
непринятые попытки; новый state содержит только принятый результат.

Минимальные поля и формы (B — число независимых документов):

| Объект | Контракт |
|---|---|
| `Frontier` | ids int64 `[B,L,K]`, mask bool той же формы, z `[B,L,K,128]`, log_beta `[B,L,K]`; padding ID=-1 не индексирует банк |
| `SolveState` | текущий F, последние Z_l, reached `[B,L]`, pending по посещённым ID, h, frozen C*, critic_version, E_old/E_best, BudgetLedger |
| `DocumentState` | document_id, absolute_byte_position, global_hop_clock; m `[B,L,N,32]`, memory_timestamp `[B,L,N]`; a/r/adaptation_timestamp `[B,L,N]`; history, ridge и их абсолютные позиции |
| `PendingWrite` | уникальный `(document,level,node)`, последний принятый z и его occurrence_id; derived memory пересчитывается при коррекции, повторная запись заменяет прежнюю |
| `Occurrence` | producer_id, parameter_version, адреса входов/выходов, локальные входы, z/log_beta, accepted, зависимости commit/history и teacher-credit horizon |
| `CriticOutput` | purpose, value, при запросе derivatives по именованным входам, validity, context/version hashes и CostRecord |
| `Proposal` | candidate F/Z/pending, явные read dependencies, sampled IDs/log-prob, operations upper bound; исходный state не меняет |
| `Trace` | порядок событий, RNG keys, назначения, сообщения, оценки, все пробы alpha, accept/reject, затраты/credit, halt reason; targets отсутствуют |
| `TrainerTargets` | отдельные labels/masks, detached teacher values/gradients, producer/consumer versions и horizon; не передаётся в step |

Начальная a=0, r=1, память/история пусты; source RNG использует также seed,
level и ordinal выбора/попытки. История — кольцевой буфер максимум 1023 записей
на уровень, с valid и absolute position, а не календарный индекс по модулю без
проверки. Состояния имеют функциональные clone/detach; сериализуется численное
состояние на границе optimizer-window, а не незавершённый autograd-граф.
Если checkpoint запрошен внутри окна, сначала завершить его либо сохранить
вход окна и точный replay-журнал; нельзя продолжить с потерянными градиентами.

Порядок одного байта: разрешить созревшие ridge-записи → сделать снимки памяти,
истории и C* → зарезервировать завершение и оценить E_initial → для каждого
предложения зарезервировать верхнюю цену → выбрать получателей → выполнить
сообщения/MLP → оценить принимающие уровни и общую E → при необходимости
оплатить и проверить коррекцию → принять либо отклонить → списать фактическую
цену, учесть реальную усталость и единственный credit → проверить halt →
получить logits из последнего Z_3 → commit памяти и истории ровно один раз.
При выключенных критиках/бюджете соответствующие шаги отсутствуют и не создают
фиктивные затраты. При отклонении меняются ledger и a/r, но не Z/pending.

## 16. Профилирование и ограничения ресурсов

MLP узла: 9216 MAC на исполнение. 60 узлов × 3 уровня — 1 658 880 MAC на
байт-хоп только для MLP. Это не оценка всей модели: routing может стоить дороже,
а последовательная память уменьшает параллелизм по t.

При заполненных трёх наборах K=60 обычные семь блоков дают 7×K×N=430 080
оценок рёбер за хоп; при d_addr=32 только dot products — около 13,76 млн MAC,
без перемычек и проекций. Поэтому небольшая доля активных MLP сама по себе
не делает весь хоп дешёвым. T_type*z_j переиспользуется для однотипных рёбер,
а P_l*m_i для snapshot памяти вычисляется один раз на байт, если это эквивалентно
эталону. При большом расходе router будущий контроль — иерархический shortlist
кандидатов, с отдельной проверкой потери покрытия и полезных маршрутов.

Для ориентира, полное сохранение только состояний 60×3×128 при B=4,T=1023
занимает около 359,65 MiB FP32 на хоп и 7,02 GiB на 20 хопов, без остального
графа. В потоковом варианте форма и пик иные; нужны реальные измерения.
Первый pilot — малый B/W, затем масштабирование. Checkpoint recompute требует
воспроизводимых маршрутов и функциональных обновлений state; нельзя повторно
списать бюджет или записать память при backward-replay.

Профиль: warmup и несколько повторов, изолированное устройство, синхронизация
измерений, отдельно inference/training/critic-fit. Предварительно проверить
фактическое железо: старые упоминания GB10 и RTX 3080 не задают текущий ресурс.
Не останавливать чужие/прежние прогоны; запланировать очередь и сохранить состояния.
Статистика процессов и текущих очередей получается заново перед будущим запуском.

## 17. Checkpoint, воспроизводимость и визуализация

Сохранять config/version, source hashes, factory, tokenizer/boundary, split hashes,
точные байтовые caps/cursors, slow weights, optimizer groups/names/moments,
critic versions, frozen cost model, EMA загрузки, все RNG и DocumentState каждого
открытого документа. Дополнительно — pending targets MTP, credit-horizon,
план teacher-pass, precision/compile flags, ledger всех предъявлений и вычислений.

Atomic checkpoint через временный файл; фиксированные точки 0,25/1/3/10 МБ.
Resume при несовместимом protocol/source hash отклоняется. Провалившиеся попытки
сохраняются и не наследуются молча следующими. Каждый завершённый этап очереди
имеет неизменяемые веса и метрики. Статус «обучение завершено» отделён от
«оценка завершена» и «генерация прочитана».

Viewer показывает настоящий N=1024 без агрегации, K по уровням, адреса сообщений,
раздельно z/m/a/r, E/V, предложение/принятие/credit, реальную цену, восемь горизонтов
и прямые logits отдельно от ridge. Единые шкалы между моделями/байтами/хопами;
CPU FP32 replay подписывается отдельно от исторического CUDA BF16 обучения.
Яркость не является полезностью, кольца не означают физическую фазу.

## 18. Не потерянные дополнительные направления

Они входят в backlog, но не добавляются одновременно к первой машине:

* Собственный векторный synthetic-gradient critic как контроль ограничения
  скалярного потенциала; условный FF на неверном продолжении/связывании вместо
  только перестановки байтов. Снижение FF-goodness loss проверяется через CE.
* Обучаемая температура единственного чтения; кредит всех горизонтов и всех
  реально влияющих occurrence. Это отдельные оси, не объяснение разрыва без замера.
* Ограниченные временные профили, eligibility по нескольким шкалам и линии задержки
  1…4; фиксированная суммарная громкость сама по себе уже не спасла старое правило.
* Мембранный интегратор, порог, рефрактерность, бинарные спайки и STDP — отдельный
  режим с объявленным обучающим сигналом. Аналоговый пакет остаётся контролем.
* Осцилляторная фаза/временной код: отдельно от RoPE и Fourier-KAN, с контролем
  числа параметров и проверкой порядка/адресации. Фаза не объявляется семантикой.
* Возбуждение/торможение и раздельные каналы содержимого/управления: проверять
  положительные/отрицательные сообщения и подавление активности без стирания памяти.
* KAN, перемычки, перенос приращений и обмен с сохранением нормы: исходные сильные
  положительные skip разгоняли общий компонент. Добавлять только отдельными парами.
* Стоимость узла, ребра и критика; адаптивное K в дополнение к адаптивным хопам;
  изменение K на inference без соответствующего обучения — отдельный stress test.
* Официальный Muon для матриц и Adam для остальных параметров после выбора
  работающей архитектуры; не путать их с прежними самописными reading-time шагами.
* Пластичность при чтении, точная память документа, обучение под адаптацию,
  shared versus separate attention: проверять дополнительность выигрышей.
* Перенос на BPE/Qwen tokenizer — после байтового эталона, с равным текстовым
  бюджетом, отдельными token/byte метриками и учётом размера словаря.

## 19. Источники биологических аналогий и математических методов

Биологические факты, теоретические модели и наш инженерный перенос разделены.
Ни один источник не доказывает полезность предложенной комбинации для DRREM.

* [Mante et al., 2013](https://www.nature.com/articles/nature12742): контекст и динамика популяции.
* [Branco et al., 2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC6354899/): различение порядка входов дендритами.
* [Mongillo et al., 2008](https://pubmed.ncbi.nlm.nih.gov/18339943/): модель рабочей памяти через кратковременную синаптическую пластичность.
* [Tsodyks–Markram, 1997](https://www.cns.nyu.edu/csh/csh04/Articles/Tsodyks-Markram-97.pdf): зависимость передачи от использования синапса.
* [Yagishita et al., 2014](https://pubmed.ncbi.nlm.nih.gov/25258080/): временное окно дофаминовой модуляции пластичности.
* [Steinberg et al., 2013](https://www.nature.com/articles/nn.3413): причинная проверка сигнала ошибки предсказания награды.
* [Rao–Ballard, 1999](https://www.nature.com/articles/nn0199_79): модель predictive coding, не установленный универсальный алгоритм коры.
* [Shazeer et al., 2017](https://arxiv.org/abs/1701.06538): sparse mixture of experts.
* [Jaderberg et al., 2017](https://proceedings.mlr.press/v70/jaderberg17a.html): synthetic gradients.
* [Czarnecki et al., 2017](https://arxiv.org/abs/1706.04859): обучение значениям и производным.
